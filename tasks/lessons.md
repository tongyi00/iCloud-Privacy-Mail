# Lessons

## 2026-08-07 — PowerShell foreach 输出先收集再管道化

- 失败模式：在 `foreach (...) { ... }` 语句后直接接 `| Format-Table`，PowerShell 将其解析为空管道元素。
- 检测信号：解析器报错 `An empty pipe element is not allowed`。
- 预防规则：需要格式化循环输出时使用 `$rows = foreach (...) { ... }`，再执行 `$rows | Format-Table`。

## 2026-08-07 — Windows 下用 rg 的 glob 参数

- 失败模式：把 `internal\\app\\*_test.go` 作为路径传给 `rg`，Windows 未展开通配符并返回路径语法错误。
- 检测信号：`rg` 报错 `os error 123`，指出文件名或卷标语法不正确。
- 预防规则：Windows 下给 `rg` 使用 `-g '*_test.go'`，目录单独作为搜索路径。

## 2026-08-07 — 先确认验证码读取语义再判定并发缺陷

- 失败模式：把 `LastCodeMessageID` 理解为必须保证验证码至多发放一次，并将并发重复返回判定为缺陷。
- 检测信号：用户明确要求有效验证码可被所有请求重复读取，多次返回没有问题。
- 预防规则：涉及“领取、消费、读取”的状态行为，先确认领域语义；本项目的验证码查询是幂等读取，不是消费操作。

## 2026-08-07 — 临时诊断探针也先核对导入

- 失败模式：新增最小诊断测试时遗漏 `os` 和 `strings` 导入，测试尚未运行就会编译失败。
- 检测信号：补丁复读时发现测试体使用了未导入的包名。
- 预防规则：每次新增 Go 探针后先复读 import 与符号，再运行目标测试。

## 2026-08-06 — 验证码 HTML 色值与语言上下文

- 失败模式：初始探针使用了中文“验证码”，掩盖了日文邮件未命中上下文关键词时，回退正则会把 `#202123` CSS 色值作为首个六码返回的问题。
- 检测信号：使用“ChatGPT の一時的な認証コード”与 HTML 色值的真实结构时，`extractOTP` 返回 `202123` 而非可见验证码。
- 预防规则：验证码解析回归必须覆盖实际邮件语言和 HTML/CSS 结构，且直接调用生产提取函数。

## 2026-08-05 — HTML 邮件预览

- 失败模式：将邮件 HTML 在入库前去标签，再按纯文本渲染，导致 CSS 源码直接展示。
- 检测信号：包含 `<style>` 的 multipart/alternative 邮件无法生成沙箱 iframe 预览。
- 预防规则：需要显示邮件正文时保留优先的 HTML MIME 分支，并仅在无脚本、无同源权限的 iframe 中渲染。

## 2026-08-05 — HTML 回补阻塞邮件查看

- 失败模式：查看旧 HTML 邮件时同步回补与后台监听争用 owner 级同步锁，前端无限等待同步请求。
- 检测信号：旧缓存命中 CSS 残留判定后，“显示邮件”持续显示加载状态，且同 owner 的 IMAP 监听连接活跃。
- 预防规则：邮件查看必须先展示本地缓存；回补同步应有独立超时和取消机制，不能阻塞弹窗。

## 2026-08-07 — 批量事务在落盘前失败也要回滚

- 失败模式：批量同步先修改第一项，随后第二项归属校验失败；由于尚未调用保存函数，通用保存失败回滚不会触发，内存会残留部分修改。
- 检测信号：审查批量提交时发现错误返回路径位于首次状态修改之后、最终保存之前。
- 预防规则：批量事务必须先完成全量校验，或在入口保存旧快照并对所有错误出口统一回滚，不能只依赖落盘函数处理失败。

## 2026-08-07 — Release 校验文件要按目标资产继续查找

- 失败模式：把首个名称含 `sha256` 的 Release 资产当作统一清单；若它是其他二进制的 sidecar，会提前停止并错过后续有效 checksums 文件。
- 检测信号：在目标资产与统一清单之间插入无关 `.sha256` 后，`ApplyAvailable` 错误变为 false。
- 预防规则：先精确匹配目标资产同名 sidecar；否则逐个解析统一清单，只有找到目标资产摘要才停止。

## 2026-08-07 — 配置校验必须覆盖文件缺失分支

- 失败模式：只在空路径和成功读取配置文件后校验 `public_base_url`，默认配置文件不存在时直接返回环境配置，导致非法环境变量绕过启动校验。
- 检测信号：`LoadConfig` 的 `os.ErrNotExist` 分支仍返回未经验证的 `cfg`。
- 预防规则：配置加载的所有成功出口都必须汇入同一个最终校验函数，特别覆盖“文件不存在但允许启动”的默认路径。

## 2026-08-07 — 先验证 http.Server.Shutdown 的标准库语义

- 失败模式：仅根据过期 context 推断 `Shutdown` 不会关闭监听器，误判进程可能永久阻塞在 `ListenAndServe`。
- 检测信号：最小监听器探针显示该推断与标准库执行顺序不符；`Shutdown` 会先关闭监听器，再等待连接或返回 context 错误。
- 预防规则：涉及标准库生命周期顺序的审查结论，先查实现或做最小状态探针，不能只根据返回错误推断副作用未发生。

## 2026-08-10 — 用户消息必须按原文解析，不能把「继续」读成空消息

- 失败模式：用户连续三次回复「继续」，被误判为空消息「.」，反过来追问是否误触；期间 `index.html` 已改到一半（顶栏换成下拉但 `toggleUserMenu` 未实现），页面处于不可用状态却停下等待。
- 检测信号：同一轮对话里对相同输入连续三次要求确认；用户最终反问「用中文告诉我你为什么停下」。
- 预防规则：不要用「消息看起来像噪声」作为停下的理由；按原文处理用户指令。已获明确批准的阶段不再重复确认。改动到一半且页面不可用时，优先做到可运行状态或明确回退，不要停在半迁移状态。

## 2026-08-10 — 大块 CSS 重构要同步清理被删结构的选择器

- 失败模式：删掉 4 张 quick-card 与顶栏三个 dock 容器后，`.quick-grid`/`.quick-card`/`.account-dock`/`.appearance-controls`/`.version-dock`/`.theme-select` 的规则仍留在样式表，其中响应式断点里还在给已不存在的元素设宽度。
- 检测信号：用 `grep -nE "quick-card|account-dock|version-dock"` 反查，仍在 3 个媒体查询和 2 处焦点环规则里命中。
- 预防规则：删除 DOM 结构后立刻反向 grep 其全部类名，确认样式表、媒体查询与焦点环规则一并清理；引用新令牌前先确认令牌真实存在（本次误用 `--shadow-menu`，实际为 `--shadow-dropdown`）。

## 2026-08-10 — 测响应式断点前必须确认页面没被重定向

- 失败模式：用 Playwright 跑 `/`、`/manage` 的六档断点，18 组全部 overflow=0，看起来验收通过；
  实际上未登录时前端会把这两个路由重定向到 `/login`，三组数据测的都是同一个登录页。
- 检测信号：`location.pathname` 与请求的 route 不一致；页面探针里 `userMenuTrigger`、`logToggle`
  等目标元素全部 `false`；`document.body.innerHTML.length` 只有 4597，远小于实际工作台页面。
- 预防规则：测受登录保护的页面时，先断言 `location.pathname` 等于目标路由，
  并抽查一个该页面独有的元素存在，再采集样式或布局数据。
  需要干净登录态时用独立 `-config` / `-data` 临时目录起实例，别动开发数据。
